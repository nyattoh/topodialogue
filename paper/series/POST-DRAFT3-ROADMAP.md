# 第3稿以後の検証ロードマップ

## 結論

第3稿の数値、図、7イベント型、単一ケースという位置づけは変更しない。修正するのは可搬性の主張境界である。現在の抽出器は日本語固有のパイロットであり、文化普遍モデルでも、固定的な人格推定器でもない。

後続研究では、TopoDialogueをRAGやグラフの代替物として定義しない。RAGは過去エピソードの取得、グラフは関係の保持に使える。本研究固有の対象は、観測可能な相互作用イベントと結果から、次の対話方略をユーザー制御下で更新する層である。

## Stage A — 第3稿の検証ゲート

1. 同意済み会話を少量用意する。
2. 2名が独立に7イベントを注釈する。
3. 観測一致率、Cohenのκ、陽性F1を固定する。
4. 不一致を調停した後、自動候補のprecision、recall、F1を算出する。
5. 日本語マーカーパックと閾値を、評価会話とは別の開発データで更新する。

完了条件: 主要イベントの注釈可能性を確認し、低一致ラベルは統合、再定義、または除外する。

## Stage B — 第4稿の変換損失とアクセス経路

各イベントと軌跡値を次の3層で比較する。

- 個人内ベースライン: 同じ人の別時点との違い。
- 関係内ベースライン: 同じ人間–AIペアの履歴との違い。
- 状況内ベースライン: 同じ課題・目的・制約の会話群との違い。

国籍、母語、文化圏、障害名、インターフェース種別は固定的な応答方略を割り当てる特徴にしない。言語・条件ごとにマーカーパックを版管理した後、音声、手話、記号、視線、スイッチ、触覚、AACから文字または共通イベントへ変換する際の保持、欠落、偽生成を測る。

声の震えや語気は感情・診断推定へ使わず、同じ文字列では失われうる韻律イベントとして扱う。異なるアクセス経路は文字の不完全版ではなく並列の一次経路である。

主要比較:

1. 文字化・正規化後のみ。
2. 変換 provenance 付きイベント。
3. 原経路イベントと正規化後イベントの対。
4. 利用者訂正後イベント。
5. 一つの経路を意図的に欠落させた条件。

完了条件: どの変換がどのイベントを保持、欠落、偽生成したかを報告する。同一文字列・異なる韻律の合成ケース、少なくとも二つのアクセス経路、対象経路の利用者を含むレビュー、欠損・同期ずれ・プライバシー費用を含める。

## Stage C — 第5稿の相互作用方略適応

方略候補は、通常の追質問、再フレーム、制約変更、待機、過去への再訪、ユーザーへの選択返却とする。方略の良否は、AIへの同意率だけで決めない。

観測結果:

- 明示的採用と拒否。
- 修復と再要求。
- ユーザー由来新規性とassistant-induced recurrence。
- 負担、停止、訂正、削除。
- 同じ方略を繰り返した場合の劣化。

比較条件:

1. 履歴なし。
2. テキストRAG。
3. イベント単位RAG。
4. 関係グラフによる履歴提示。
5. ユーザー制御付き方略適応。

完了条件: 方略適応の寄与を取得方式・表現方式から分離し、ユーザーが推定・履歴・表示・次の介入を訂正、拒否、削除、停止できる。

## 実装順序

1. 第3稿の人手注釈用UIまたはCLI補助を整える。
2. マーカーパックを言語・条件別設定へ分離する。
3. `source_modality`、変換手順、保持／欠落特徴、不確実性、利用者訂正を持つイベントスキーマを実装する。
4. 同一文字列・異なる韻律と、経路置換・欠落の既知合成ケースを実装する。
5. 個人内・関係内・状況内ベースラインのデータスキーマと差分計算を実装する。
6. 操作・原信号の同意、保存期間、削除仕様を実装する。
7. 方略選択ログに候補、根拠、不確実性、利用者採否、結果を保存する。
8. RAG・グラフ・適応方略を独立に切り替えられるablationを実装する。

## 中止条件

- 第3稿の主要ラベルが人手で再現できない場合、学習型抽出へ進まずラベル体系を見直す。
- 3層較正が未較正ベースラインより一貫して悪い場合、個人化の前提を撤回する。
- 追加経路がイベント保持を改善せず、アクセス負担またはプライバシー危険を増やす場合、その経路を既定にしない。
- 適応方略がユーザー負担、誘導、assistant-induced recurrenceを増やす場合、自律実行を行わず提案＋明示採否に限定する。
- より豊かなトポロジーが予測、説明、再現性を改善しない場合、導入しない。
