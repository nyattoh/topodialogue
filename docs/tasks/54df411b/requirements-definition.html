2. 中央命題と研究質問

中央命題: AIメモリは内容だけを更新するのではなく、同一のメモリ単位について、表現形式（representation form）・精度（precision）・物理配置（physical placement）を一つの「相」として同時に再構成すべきである。同じ記憶が固定形式・固定場所に居続ける必要はない。

Φ(m,t) = ⟨R(m,t), Q(m,t), L(m,t), S(m,t), Π(m,t)⟩

ここで R は表現形式、Q は数値精度、L は配置階層、S は保持する位相骨格、Π は由来と変換履歴である。相転移はこれらを別々の後処理にせず、一つの監査可能な制御判断として扱う。

主研究質問

意味状態の重要性と構造的なアクセス予測を使ってメモリの相を共同制御すると、固定配置、配置のみの階層化、圧縮のみの方式に比べ、回答品質と構造保存を制約内に保ちながら、HBM占有、転送量、遅延、総電力を改善できるか。

新規性仮説

候補となる差分は、KVキャッシュ圧縮、可逆圧縮メモリ、一般的なsoftware–hardware co-designの個別技法ではなく、意味状態の変化と半導体メモリ上の配置変化を同じ制御問題として定式化することにある。これは現時点では新規性の主張ではなく、W1の系統的調査で反証されるべき仮説である。

3. 三つの相: vapor / liquid / ice

vapor / 気相

目的: 遠い低コスト層に長期保持する。

  • 疎・圧縮・低精度・構造中心の表現。
  • 重複内容を統合し、重要な遷移、分岐、再訪、由来を残す。
  • 元テキストまたは詳細テンソルを常駐前提にしない。
  • 配置例は低コスト遠隔層。具体媒体は実験プラットフォームで宣言する。

liquid / 液相

目的: 再利用可能性がある記憶を待機させる。

  • 部分展開された中間表現。
  • 中程度の精度と容量。
  • DRAMを主要な配置候補とする。
  • vaporからの再構成とiceへの昇格の間を緩衝する。

ice / 固相

目的: 計算直近で即時利用する。

  • 詳細・高精度・即時参照可能な表現。
  • 現在のクエリ局所領域と作業集合を保持する。
  • HBM / SRAM / cacheを主要な配置候補とする。
  • 最高コスト層への無制限な常駐は許さない。
ID要件受入観点
REQ-P01各相を少なくとも表現形式・精度・配置・保持構造・復元可能性の5軸で定義する。EN/JAの対応表が同じ意味を持つ。
REQ-P02相は媒体名の別名ではない。たとえば「DRAMだからliquid」とせず、位相タプル全体で判定する。形式モデルと例で確認。
REQ-P03各メモリ単位は現在相、元データ参照、由来、変換履歴、codec/policy version、サイズ、品質検査値を持つ。architecture sketchと方法節のmanifest項目。

4. 相転移演算子

演算子は表現・精度・配置を一括して変え、その前後を監査可能にする。名称は制御の比喩であり、水の物理過程をAIメモリが再現するという主張ではない。

演算子入力 → 出力共同変更最低保持条件
evaporateice/liquid → vaportext/detail → latent/summary/sketch、低精度化、dedup、遠隔低コスト層へ移動重要遷移、主要分岐、再訪、現在のattractor-like領域への接続、順序、由来
condensevapor → liquid/iceクエリ周辺の局所領域を選択再構成し、必要精度へ拡張、計算近傍へ配置復元根拠、欠落範囲、不確実性、参照したvapor記録を残す
freezeliquid → ice詳細化・高精度化・HBM/SRAM/cacheへの昇格容量と予測便益を示し、過昇格を抑制
meltice → liquid部分縮約・必要精度への減精度・DRAMへの降格短期再利用に必要な局所構造と由来
TransitionDecision = ⟨item/region, phase_before, phase_after, trigger_evidence, expected_cost, policy_version, timestamp⟩
  • 必須: evaporate と condense を論文の中心演算子として形式化する。
  • 推奨: freeze と melt を三相間の実装補助演算子として定義し、中心命題をぼかさない。
  • 必須: 非可逆圧縮を可逆と表現しない。完全復元、近似再構成、原文への外部参照を区別する。
  • 必須: 変換失敗、品質低下、転送スラッシング、codecコスト超過を観測し、固定閾値を研究結論として扱わない。

5. 位相骨格

「位相骨格」は、圧縮後も残すべき意味軌跡の操作的な構造要約を指す。Phase-1ではグラフ・時間順序・再訪統計で実装可能な仮説であり、persistent homologyや厳密な位相不変量を前提としない。

構成保持内容候補測定
connectivity重要ノード間の到達可能性、局所近傍、主要な関係。重み付きedge/route preservation。
revisit再訪された領域、頻度、最後の再訪、再訪元。revisit-rank相関、再訪集合のprecision/recall。
branch選択や展開を分けた主要分岐点と枝の由来。branch-point recall、重要度順位一致。
attractor-like region現在または反復的に戻る局所領域。形式的attractorの主張はしない。クラスタ／再帰近傍の保持率。
transition order重要状態の前後関係と時間窓。順序制約の充足率。
provenanceuser、assistant、heuristic、model inference、原データ参照、confidence、evidence span。由来の完全性と誤帰属率。
TPR = (Σk wk · preservek) / (Σk wk), k ∈ {connectivity, revisit, branch, attractor-like, order, provenance}

Topology Preservation Rate (TPR) は探索的な複合指標であり、構成値を必ず併記する。重みは事前宣言し、感度分析を行い、単一スコアで欠落を隠さない。

iceに残す候補

  • 現在のattractor-like領域と、現在クエリに接続する局所構造。
  • 直近の重要遷移と、その根拠。
  • 高中心性だけでなく、意味的に重要な分岐点。
  • 過去に再訪された領域と、再構成コストが高い領域。
  • 由来や順序を復元するために不可欠なanchor。

6. アーキテクチャ案

本図は論文の研究アーキテクチャであり、製品UI案ではない。制御器、表現変換、配置階層、観測指標、データ流を分離し、どのコストと主張を反証できるかを示す。

データ流制御判断観測feedback

データ流

  1. 推論クエリ、メモリアクセス、意味状態グラフから観測イベントを作る。
  2. 位相骨格を更新し、現在クエリへ接続する局所領域、再訪、分岐、由来を抽出する。
  3. H2O controllerが容量・予測便益・品質予算・転送／codecコストを評価し、一つのphase transitionを決める。
  4. 表現変換器と配置管理器が同じdecision IDで変換・転送し、manifestを原子的に更新する。
  5. 取得時は必要な局所領域だけをcondense/freezeし、復元不確実性を推論側へ渡す。
  6. 電力、遅延、帯域、回答品質、TPR、失敗をcontrollerへ戻し、オフラインで方策を更新する。

7. 電力式と測定境界

Ptotal = Pinference-compute + Pmemory-retention + Pinter-memory-transfer + Pcompression/decompression

論文はこの4項を必ず分離報告する。圧縮による転送削減だけを示し、codecや再構成の電力を除外してはならない。測定区間 Δt に対して、転送・codecのイベントエネルギーを平均電力へ換算する。

Ptransfer = (Σi,j bytesi→j · ei→j) / Δt
Pcodec = (Ecompress + Edecompress + Ereconstruct) / Δt
  • 必須: 平均電力だけでなく、energy/query、測定時間、ウォームアップ、idle/staticの扱いを報告する。
  • 必須: HBM、DRAM、SRAM/cache、far tierの測定境界と、推定値／シミュレーション値／実測値を明記する。
  • 必須: 二重計上を避ける。たとえばDMAエンジンやFPGA fabricの消費をどの項へ入れたかを固定する。
  • 推奨: 合計値に加えて時間系列と相転移1回あたりの分布を提示し、スラッシングを可視化する。

8. 提案実験 — 実施済みと書かない

対象: FPGA上の単純なH2O memory controller。メモリ利用を観測し、相と配置を変え、シミュレーションおよび可能なら実機で帯域・遅延・電力を測り、方策を改善する。draft6では計画と反証条件までを示し、結果値は報告しない。

実験パイプライン

  1. 合成／匿名化した長期対話または意味状態traceと、再現可能なメモリアクセスtraceを作る。
  2. current region、recent transitions、key branches、revisited regions、query-local connectivity、provenanceから重要度を算出する。
  3. controllerがphase transitionとplacementを決める。
  4. cycle-accurate simulation、電力推定、可能な範囲のFPGA実測を区別して実行する。
  5. 帯域、遅延、電力、面積、品質、fidelity、TPRを同じtrial IDで記録する。
  6. 事前宣言した制約を満たさない結果や負の結果も含め、方策と閾値を改訂する。

比較条件

条件目的
B0 固定ice高精度・計算近傍常駐の上限品質／高コスト基準。
B1 配置のみLRU等で表現と精度を変えず階層移動し、joint controlの差分を測る。
B2 圧縮のみplacementを固定して表現／精度だけを変え、転送と配置の共同効果を分離する。
B3 recency policy位相骨格を使わない単純な最近性基準と比較する。
H2O joint表現・精度・配置を位相骨格に基づき共同制御する。

必須ablation

  • 表現変換なし、精度変更なし、配置変更なしを一つずつ除く。
  • 位相骨格なし、provenanceなし、revisitなし、branchなしを比較する。
  • codec/reconstruction電力を0と仮定した理想値と、含めた現実値を分ける。
  • hysteresis/cooldownなしの方策と比較し、phase thrashingを測る。
研究誠実性: FPGAボード、メモリ構成、クロック、電力計測手段が未確定の段階で具体的な省電力率、速度向上率、面積を置かない。論文中の図に仮の数値を使う場合は、説明用toy exampleであることを図内にも明記する。

反証可能な仮説

  • H1: H2O jointは、同等の回答品質制約下でB0/B1/B2より総電力またはenergy/queryを下げる。codecや再構成を含めて下がらなければ棄却する。
  • H2: 同じ近傍メモリ容量では、位相骨格policyがrecency policyより再構成fidelityとTPRを高くする。統計的／実用的差がなければ単純方策を採る。
  • H3: joint controlはHBM占有と転送量の両方を改善する。片方だけ改善し、遅延や品質が悪化する場合はtrade-offとして報告する。
  • H4: hysteresis/cooldownはphase thrashingを減らす。反応遅延の悪化を含めて評価し、成功前提にしない。

12. 既存TopoDialogueとの接続

TopoDialogue概念H2O Memoryへの接続混同しない点
structured semantic state x_t / graph G_tmemory item/regionの意味的importanceと局所構造を作る入力。グラフそのものを物理配置と同一視しない。
semantic recurrence / revisit再び必要になる領域の候補をice/liquidへ残す信号。再訪頻度だけで価値を決めず、品質・由来・分岐も使う。
branch / attractor-like region / transition motif圧縮時に残す位相骨格、condenseする局所領域のanchor。厳密なtopological invariantや心理状態と称さない。

接続の要点: TopoDialogueが「現在どの意味領域にいて、どこへ戻り、どの分岐と由来が重要か」を記述し、H2O controllerがその構造を使って「何をどの相でどこに置くか」を決める。既存の対話loop detectorをH2O論文の実証結果として再解釈してはならない。

13. 非実施事項と安全境界

  • FPGA実験、simulation、実電力測定、性能benchmarkの実行と、結果値の生成。
  • production memory controller、driver、RTL、cloud deployment、製品UI。
  • multi-agent orchestration、GraphRAG、persistent homology、wearable/body sensorの追加。
  • 治療、診断、臨床判断、心理状態の断定。意味状態の推論はconfidenceとevidenceを伴う仮説に限る。
  • raw personal dialogueを必須データにすること。例・テスト・traceは合成または匿名化する。
