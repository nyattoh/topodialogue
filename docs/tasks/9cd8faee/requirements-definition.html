Requirements Definition · Phase 1

H2O Memory

会話記憶を、水のように vapor / liquid / ice の一つの相として扱う。 古い領域を軽量な構造へ蒸発させ、質問に必要な領域を再び詳細な表現へ凝縮できることを、 通常のPC上で測定可能にする最小ソフトウェアプロトタイプの要件定義である。

01 / PURPOSE

証明ではなく、反証できるデモを作る

本プロトタイプの問いは「相変化という表現が魅力的か」ではない。 圧縮された記憶が実際に小さく、必要時に再構成され、位相的な選択規則と由来が監査できるかを検証する。

製品目標: 短い合成会話を取り込み、古い記憶領域を vapor へ変換し、質問に関連する領域を ice へ戻し、保存量と再構成品質を同じ実行で報告するCLIを提供する。

研究上の位置づけ: H2O Memory と TopoDialogue の組み合わせは novelty hypothesis であり、研究新規性の主張ではない。

OUTCOME 01

相が変わる

同じ memory_id を持つ領域が、明示的な状態機械を通って ice / liquid / vapor 間を往復する。

OUTCOME 02

小さくなる

canonical serialization による比較で、vapor の総バイト数が元の ice より小さいことを示す。

OUTCOME 03

戻して測る

質問から関連領域を選び、ice を再構成し、本文・順序・グラフ・provenance の回復率を出力する。

用語境界: Phase 1 の topology は、意味再訪と時間グラフ構造を扱う研究メタファー／構造仮説である。グラフサイクルや以下の指標を数学的な位相不変量として扱わない。

02 / PHASE MODEL

一つの記憶、三つの表現状態

相は別コピーではなく、安定した識別子と来歴を共有する同一記憶の表現形・精度・論理配置である。

VAPOR · compressed cold

構造だけを表面に残す

  • topology skeleton、最小メタデータ、provenance索引
  • 疎／量子化された特徴と圧縮 recovery capsule
  • 詳細本文は通常の参照面に展開しない
  • 論理配置: compressed_cold
LIQUID · serialized standby

すぐ戻せる待機状態

  • 要約、低〜中精度特徴、近傍リンク
  • 完全な evidence 索引と transition record
  • 詳細payloadは非展開または部分展開
  • 論理配置: standby_serialized
ICE · active near compute

計算に使う詳細状態

  • 発話、型付きノード／エッジ、完全精度特徴
  • evidence span、confidence、correction history
  • 検索・測定から直接利用可能
  • 論理配置: active_objects

公開APIの vaporize() と condense() は複合操作でよいが、監査ログでは ICE → LIQUID → VAPOR、VAPOR → LIQUID → ICE の各遷移を残す。 「physical placement」は Phase 1 では上記の論理配置で模擬し、実RAM階層・GPU転送・消費電力を実装済みと表現しない。

可逆性の定義: vapor の通常表面は structure-only だが、vaporサイズに含めて計測する lossless recovery capsule を保持する。condense 後は合成fixtureの本文、順序、グラフ、provenance、訂正履歴を完全回復する。特徴量は同じ決定論的providerから再計算して高精度化できる。

04 / TOPOLOGY

「残す／蒸発させる」を説明可能にする

時間グラフは発話・意味領域をnode、観測された遷移・類似・訂正参照をedgeとして持つ。各指標は0〜1へ正規化し、値と根拠nodeを出力する。

指標Phase 1 操作的定義保持への意味必須evidence
connectivity対象regionの異なる隣接region数 ÷ max(1, N-1)多領域を結ぶhubほどactive側隣接region IDとedge種別
revisitmin(1, revisit_count / revisit_cap)。閾値以上の意味類似で戻った回数再参照される領域ほどactive側再訪turn ID、類似度、閾値
branchmin(1, distinct_successors / branch_cap)選択肢の分岐点ほどactive側順序付きsuccessor ID
attractor0.6 × revisit + 0.4 × normalized_dwell繰り返し滞在する構造を保持revisit、連続滞在長
transition_orderすべての時間edgeへ単調増加 sequence_no を付与凝縮時の会話順を再構成edge ID、sequence_no
provenance_coverage有効なsourceとevidenceを持つnode数 ÷ 全node数監査不能な圧縮を防ぐsource、evidence span/hash
retention_score = .25C + .25R + .15B + .25A + .10P
score ≥ .65 → ICE · .35 ≤ score < .65 → LIQUID · score < .35 → VAPOR

係数と閾値は設定可能なテスト初期値であり研究結論ではない。明示的な safety_hold、未解決訂正、schema versionはpinされ、scoreより優先してiceまたは常時参照可能なskeletonへ残る。上書き理由は監査ログに記録する。

DETERMINISTIC

同点規則

同じscoreなら region_id の昇順。集合走査やhash順に結果を依存させない。

QUERY PATH

凝縮候補

query関連度上位のskeletonから1-hop近傍を候補化し、上限 top_k 内だけをcondenseする。

HONEST LABEL

attractorの意味

心理状態ではなく「グラフ上で再訪と滞在が高い領域」という操作ラベルに限定する。

05 / DATA & PROVENANCE

圧縮しても、誰が何から作ったかを失わない

観測発話、抽出構造、推論、評価結果を混同しない。すべての派生nodeはconfidenceとevidenceを持つ。

  • 明示されていない心理・感情・身体状態を事実として保存しない。

08 / MEASUREMENT

保存量と回復を、同じ物差しで測る

Python objectの sys.getsizeof は実装差が大きいため受入判定に使わない。sorted keys・余白なしのcanonical JSON UTF-8 bytesと、圧縮capsule実bytesを合計する。

saving_ratio = 1 − vapor_total_bytes / original_ice_canonical_bytes
text_recovery = exactly_matched_turns / original_turns
graph_recovery = harmonic_mean(node_recall, edge_recall) · order_fidelity = preserved_order_pairs / original_order_pairs
SIZE

圧縮payloadも数える

skeleton、索引、header、checksum、recovery capsuleをすべてvapor側へ算入する。

CONTENT

本文と特徴を分離

本文exact matchと特徴cosineを別々に報告し、片方で他方の失敗を隠さない。

STRUCTURE

順序と来歴を一級指標に

node/edgeだけでなくtransition order、source、evidence、correctionの回復を測る。

metric固定fixture受入閾値表示精度失敗条件
saving_ratio≥ 0.20小数4桁capsule除外、負値、20%未満
text_recovery= 1.0小数4桁1 turnでも不一致
feature_cosine≥ 0.999（deterministic provider）小数4桁provider fingerprint不一致または閾値未達
node_recall / edge_recall= 1.0 / 1.0小数4桁IDまたは型付きedge欠落
order_fidelity= 1.0小数4桁順序pairの逆転・欠落
provenance_recall= 1.0小数4桁source/evidence/correction欠落

20%は圧縮可能な固定合成fixtureに対する工学的gateであり、自然会話一般の保存率を主張しない。別入力で値が悪化した場合も、その値をそのまま報告する。

10 / BOUNDARIES

安全・非機能・対象外

記憶圧縮デモを、臨床判断や大規模基盤へ膨らませない。安全に関する明示情報は「蒸発させて見えなくする」対象にしない。

SAFETY

非臨床

診断、治療、心理状態の真偽判定を行わない。distress/uncertaintyは明示発話または入力metadataに限る。

PRIVACY

local-first

raw personal dialogueをテスト・ログ・commitへ含めない。デモは合成fixture、外部送信なし。

AGENCY

生成をしない

H2O Memory CLIは内省質問や助言を生成しない。記憶取得は上位のsafety pauseを上書きしない。
