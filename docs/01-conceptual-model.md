# 01 — Conceptual model

## 1. From linear turns to a dialogue state trajectory
A chat transcript is stored as a sequence of turns, but the research object is not the text sequence itself. Each turn updates a structured semantic state.

Let:

- `u_t`: user turn at time t
- `a_t`: assistant turn at time t
- `x_t`: structured state snapshot after processing the turn pair
- `z_t`: dense embedding representation of the local dialogue state
- `G_t`: cumulative temporal semantic graph

The observed trajectory is:

`x_1 -> x_2 -> ... -> x_t`

with a parallel dense trajectory:

`z_1, z_2, ..., z_t`.

The dense trajectory is useful for neighborhood recurrence. The graph is useful for provenance, contradictions, simultaneous relations, repeated motifs, and interpretable state changes.

## 2. Relation to the supplied Topo concept
The source text defines Topo as:

`Topo := (V, E, w, tau, m, kappa)`

with heterogeneous nodes for affect, body, concept, context; relation edges; strength/confidence; temporal simultaneity; masking/granularity; and context curvature.

For the Phase-1 dialogue prototype, use a deliberately reduced operational form:

`DialogueTopo_t := (V_t, E_t, W_t, T_t, P_t)`

where:
- `V_t` = typed semantic nodes
- `E_t` = typed directed/multi-edges
- `W_t` = confidence, salience, activation
- `T_t` = temporal provenance and co-occurrence
- `P_t` = provenance: user / assistant / extractor / heuristic

Do **not** implement `m` (masking/body gate) or `kappa` (context curvature) in Phase 1. Preserve extension points in the schema.

## 3. Typed nodes
Minimum node types:
- `Concept`
- `Affect`
- `Body`
- `Context`
- `Desire`
- `Constraint`
- `Value`
- `SelfClaim`
- `Counterfactual`
- `ActionPattern`
- `Uncertainty`

A node is not a fact about the person. It is a state hypothesis with confidence and supporting evidence.

Example:

`SelfClaim("I do not have things I want", confidence=.82, source=user, evidence=turn_12)`

can coexist with:

`Desire("travel to unfamiliar landscape", confidence=.91, source=user, evidence=turn_27)`

and an edge:

`changes_under(SelfClaim, ConstraintSetRemoved)`.

The graph should preserve the contradiction rather than overwrite the earlier claim.

## 4. Dialogue loop as a dynamical phenomenon
A loop is not exact textual repetition. It is a recurrent region in the state trajectory with low semantic progress.

Informally:

`same region + repeated transition motif + little user-originated novelty = candidate loop`

An attractor-like basin is a cluster or neighborhood repeatedly revisited under ordinary local follow-up.

Important: use **attractor-like** as descriptive language unless formal dynamical criteria are demonstrated.

## 5. Local search versus coordinate transformation
Ordinary follow-up often changes the query while preserving the frame:

- “What do you want?”
- “What did you enjoy before?”
- “What would make tomorrow meaningful?”

These are local searches in roughly the same coordinate system.

A transformation operator changes a hidden assumption or representation:

- remove feasibility constraints;
- invert valence: ask what the user rejects instead of likes;
- switch object -> operation/pattern;
- find a counterexample to a global self-claim;
- move from identity (“what are you?”) to trajectory (“what do you keep doing?”);
- change time horizon or agent perspective.

The operator's purpose is not to force optimism; it is to create a testable route to a previously inaccessible semantic region.

## 6. Formative pattern
A recurrent self-claim such as “I do not know what I want” may be stable under local follow-ups. If a `ConstraintRemoval` operator produces an immediate increase in user-originated desires, one plausible interpretation is:

`desire absence` was not the only explanation;

`desire generation -> feasibility filter -> early rejection`

may better explain the observed dialogue.

This is a hypothesis generated by the transition, not a diagnosis.

## 7. Transition memory
The system should eventually store episodes as:

`LoopSignature -> Operator -> Outcome`

Example:

- signature: repeated SelfClaim + high Constraint activation + low novelty
- operator: `ConstraintRemoval`
- outcome: strong new Desire nodes introduced by user

This is the basis of the proposed **Transition RAG**: retrieve prior successful state transitions, not merely semantically similar past text.

## 8. Separation of layers
Keep three layers distinct:

1. **State representation** — what is active now?
2. **Dynamics** — are we revisiting the same region / making progress?
3. **Dialogue policy** — continue locally or apply an operator?

Do not collapse them into a single prompt.
